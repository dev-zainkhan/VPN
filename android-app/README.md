# Veil Android app

React Native (Expo SDK 54) app with a native WireGuard tunnel. Screens follow
`../docs/front end/VPN App  MVP Screens.pdf`; the API is section 8 of the backend spec.

## Get a test build (no Android tools needed)

Every push to `main` that touches `android-app/` builds the app in GitHub Actions
(`.github/workflows/android.yml`) and replaces the APK in the `android-test` release.

On the phone, open
https://github.com/dev-zainkhan/VPN/releases/download/android-test/veil-test.apk,
download it and install it (allow "Install unknown apps" for the browser or the GitHub app once).
A newer build installs over the old one and keeps the app's data.

Test builds talk to the API at `http://192.168.1.27:3000` (the dev laptop on the same Wi-Fi).
If the laptop gets another address, change it in the app: **Settings → Test build → Server address**,
or set the repository variable `VEIL_API_BASE` and run the workflow again.

## How it works

| Part | File |
| --- | --- |
| Native module: VPN permission, WireGuard tunnel (official `com.wireguard.android:tunnel`), keys, TCP-over-TLS forwarder, ping | `modules/veil-vpn/` |
| Device API client | `src/services/api.ts` |
| Registration, abuse key, WireGuard key pair (kept in encrypted storage) | `src/services/identity.ts` |
| Tunnel config from the connect response; Auto mode handshake check | `src/services/tunnel.ts` |
| Screens and app flow | `App.tsx`, `src/features/` |
| Build settings (API address, test build, version code) | `app.config.js` |

- Auto protocol: UDP first; if no WireGuard handshake within 8 seconds, it reconnects over TCP 443.
- The app's own API traffic and local networks stay outside the tunnel; IPv6 goes in and is dropped.
- While connected the app asks the server for the balance every minute and stops at zero.
- Kill switch: Android's "Always-on VPN" + "Block connections without VPN" (Settings has a shortcut).
